================================================================
Сеть Фейстеля (Type-2 GFN, 4 ветви) + CFB-64 + PRESENT S-Box
================================================================

ОПИСАНИЕ ПРОЕКТА
----------------------------------------------------------------
Реализация обобщённой сети Фейстеля (Generalized Feistel
Network, Type-2) с четырьмя ветвями по 16 бит, 16 раундами,
режимом сцепления блоков CFB-64, S-Box из шифра PRESENT и
случайным IV. Сообщение и ключ вводятся в бинарном или
hex-формате. Поддерживается шифрование и расшифрование.
Ключ принимается любой длины от 128 бит, не обязательно
кратной 64.

----------------------------------------------------------------
1. S-BOX ИЗ ШИФРА PRESENT
----------------------------------------------------------------
Что взяли: 4-битный S-Box из лёгкого SPN-шифра PRESENT.
Источник: Bogdanov et al., "PRESENT: An Ultra-Lightweight
Block Cipher", 2007.

Таблица замены (вход -> выход):
0 -> C,  1 -> 5,  2 -> 6,  3 -> B,
4 -> 9,  5 -> 0,  6 -> A,  7 -> D,
8 -> 3,  9 -> A,  A -> 6,  B -> C,
C -> 5,  D -> 9,  E -> 0,  F -> 7.

Почему именно он:
- Размер совпадает: наши ветви оперируют 16-битными
  строками, S-Box применяется к каждому нибблу.
- Готовый и проверенный: стандартный S-Box, прошедший
  многолетний криптоанализ.
- Консистентность: тот же S-Box, что и в SPN-проекте.
  Удобно сравнивать два шифра на одной базе.
- Лёгкость: маленькая таблица, быстро работает.

ВАЖНОЕ ОТЛИЧИЕ ОТ SPN: в SPN S-Box обязан быть обратимым,
потому что расшифрование требует обратной замены. В сети
Фейстеля S-Box может быть любой — даже необратимой.
Обратимость всей конструкции обеспечивается структурой
сети, а не отдельными компонентами.

----------------------------------------------------------------
2. РЕЖИМ ШИФРОВАНИЯ: CFB-64 (CIPHER FEEDBACK)
----------------------------------------------------------------
Проблема ECB: каждый блок шифруется отдельно, одинаковые
блоки дают одинаковый шифротекст. Утечка структуры.

CFB — потоковый режим, превращающий блочный шифр в
генератор гаммы.

Формулы шифрования:
C[0] = E(IV) XOR P[0]
C[i] = E(C[i-1]) XOR P[i],  i >= 1

Формулы расшифрования:
P[0] = E(IV) XOR C[0]
P[i] = E(C[i-1]) XOR C[i],  i >= 1

Ключевая идея: предыдущий шифроблок шифруется и XOR-ится
с текущим открытым текстом. Функция расшифрования блочного
шифра НЕ используется вообще — только E.

Почему выбрали CFB (а не PCBC, как в SPN):
- Другой класс режимов: PCBC — блочный с цепочкой,
  CFB — потоковый. Интересно сравнить.
- Обратная функция D не нужна: расшифрование тоже
  использует E. Для сети Фейстеля это не критично
  (у неё и так нет обратной F), но концептуально
  красиво.
- Ошибка в одном блоке портит текущий и следующий,
  дальше всё восстанавливается. В PCBC портилось всё
  до конца.
- Демонстрирует, что блочный шифр можно превратить
  в потоковый генератор.

----------------------------------------------------------------
3. ГЕНЕРАЦИЯ ПОДКЛЮЧЕЙ (KEY SCHEDULE)
----------------------------------------------------------------
Задача: из мастер-ключа длиной от 128 бит получить ровно
16 подключей по 16 бит — по одному на каждый раунд.

Алгоритм:
1. Берём первые 128 бит ключа, делим на 8 слов по 16 бит:
   K[0], K[1], ..., K[7].
2. Если ключ длиннее 128 бит — остаток дополняем нулями
   до кратности 16 и XOR-им по кругу в K[0..7]. Так весь
   ключ влияет на подключи.
3. Для каждого раунда r = 1..16:
   subkey = K[r mod 8] XOR r_16bit
   затем обновляем все K:
   K[i] = K[i] XOR ROTL(K[(i+1) mod 8], r+1)
   где ROTL — циклический сдвиг влево, r_16bit — номер
   раунда в 16-битном представлении.
4. Получаем 16 разных подключей.

Идея: циклический сдвиг на разное число бит в каждом
раунде + XOR со счётчиком раунда гарантируют, что все
16 подключей разные и зависят от всего ключа.

Важно: key schedule — детерминированная функция. Она НЕ
требует, чтобы ключ был кратен 64 битам. Если остаток
короче 16 бит, он дополняется нулями до 16 бит и XOR-ится.
Это часть key schedule, а не "паддинг ключа".

Примеры:
128 бит  -> 8 слов без остатка.
136 бит  -> остаток 8 бит, паддится до 16, XOR в K[0].
160 бит  -> остаток 32 бита, XOR в K[0], K[1].
200 бит  -> остаток 72 бита, паддится до 80, XOR в K[0..4].
256 бит  -> остаток 128 бит, XOR во все K[0..7].

----------------------------------------------------------------
4. КАК РАБОТАЕТ СЕТЬ ФЕЙСТЕЛЯ
----------------------------------------------------------------
Классическая сеть Фейстеля делит блок на две половины L и R
и за раунд выполняет:
L' = R
R' = L XOR F(R, K)

Главное свойство: F НЕ обязана быть обратимой. Обратимость
всей конструкции обеспечивается структурой сети — при
расшифровании те же операции идут с подключами в обратном
порядке.

Наша версия — Type-2 GFN с 4 ветвями. Блок 64 бита делится
на четыре части по 16 бит: A, B, C, D. За раунд:
new_D = A XOR F(B, K_i)
(A, B, C, D) <- (B, C, D, new_D)

То есть: берём A и B, считаем F(B, K_i), XOR-им с A —
получаем new_D. Затем сдвигаем всё влево: A становится B,
B становится C, C становится D, D становится new_D. Через
четыре раунда каждая часть повлияет на все остальные.

Расшифрование — сдвиг вправо:
new_A = D XOR F(A, K_i)
(A, B, C, D) <- (new_A, A, B, C)
Подключи идут в обратном порядке. Функция F остаётся той
же самой — никаких обратных S-box не нужно.

Раундовая функция: F(x, k) = S(x XOR k), где S — применение
4-битного S-box к каждому нибблу. XOR даёт зависимость от
ключа, S-box даёт нелинейность.

----------------------------------------------------------------
5. IV (INITIALIZATION VECTOR)
----------------------------------------------------------------
Что такое IV: случайное число размером с блок (64 бита),
которое подмешивается при шифровании.

Зачем нужен:
- Без IV одинаковые сообщения при одном ключе дают
  одинаковый шифротекст — утечка.
- С IV шифротекст каждый раз разный, даже если сообщение
  то же самое.

Свойства IV:
- Не секретный: передаётся открыто вместе с шифротекстом.
- Уникальный: генерируется заново при каждом шифровании.
- Размер = размер блока: 64 бита.
- Нужен при расшифровании: без него нельзя восстановить
  первый блок.

В нашем коде IV генерируется случайно, выводится в BIN и
HEX. Его нужно сохранить, чтобы потом расшифровать
сообщение тем же ключом.

----------------------------------------------------------------
6. ОБЩАЯ СХЕМА РАБОТЫ
----------------------------------------------------------------
Шифрование:
1. Ввод сообщения (BIN или HEX).
2. Разбиение на блоки по 64 бита (паддинг нулями).
3. Генерация 16 подключей из мастер-ключа.
4. Генерация случайного IV (64 бита).
5. Для каждого блока:
   - keystream = E(prev), где prev = IV для первого блока
     или предыдущий шифроблок.
   - C = P XOR keystream.
   - 16 раундов внутри E: A,B,C,D -> new_D = A XOR F(B,K),
     сдвиг влево.
6. Вывод шифротекста (BIN и HEX) и IV.

Расшифрование:
1. Ввод шифротекста, ключа, IV.
2. Разбиение на блоки по 64 бита.
3. Генерация тех же 16 подключей.
4. Для каждого блока:
   - keystream = E(prev) — та же самая функция E, что
     и при шифровании. Обратная D не нужна.
   - P = C XOR keystream.
5. Вывод исходного сообщения.

----------------------------------------------------------------
7. ПРИМЕР РАБОЧЕГО НАБОРА
----------------------------------------------------------------
Сообщение (HEX, 64 символа = 256 бит):

Ключ (HEX, 32 символа = 128 бит):

Сообщение (BIN, 256 бит):

Ключ (BIN, 128 бит):
10110100101101001011010010110100101101001011010010110100101101000110110011011000110110001101100011011000110110001101100011011000

Как проверить:
1. Запустить программу, выбрать пункт 1.
2. Вставить сообщение и ключ.
3. Скопировать шифротекст и IV.
4. Выбрать пункт 2, вставить шифротекст, ключ и IV.
5. Должно получиться исходное сообщение.

----------------------------------------------------------------
8. ОТЛИЧИЯ ОТ SPN-ПРОЕКТА
----------------------------------------------------------------
Структура: SPN — одна ветвь, Фейстель — 4 ветви.
Обратимость F: в SPN S-box обязан быть обратимым, в
Фейстеле — может быть любым.
Раундов: SPN — 10, Фейстель — 16.
Режим: SPN — PCBC, Фейстель — CFB.
Расшифрование: в SPN — обратные S-box и перестановка,
в Фейстеле — те же операции в обратном порядке подключей.
S-box: в обоих проектах — PRESENT, 4 бита.
