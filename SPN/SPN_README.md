================================================================
SPN + PCBC + PRESENT S-Box + ISO 7816-4 Padding
================================================================

ОПИСАНИЕ ПРОЕКТА
----------------------------------------------------------------
Реализация SPN-шифра (Substitution-Permutation Network) с
10 раундами, режимом сцепления блоков PCBC, S-Box из шифра
PRESENT, паддингом по стандарту ISO 7816-4 и случайным IV.
Сообщение и ключ вводятся в бинарном или hex-формате.
Поддерживается шифрование и расшифрование.

----------------------------------------------------------------
1. S-BOX ИЗ ШИФРА PRESENT
----------------------------------------------------------------
Что взяли: 4-битный S-Box из лёгкого SPN-шифра PRESENT.
Источник: Bogdanov et al., "PRESENT: An Ultra-Lightweight
Block Cipher", 2007.

Таблица замены (вход -> выход):
0 -> C,  1 -> 5,  2 -> 6,  3 -> B,
4 -> 9,  5 -> 0,  6 -> A,  7 -> D,
8 -> 3,  9 -> E,  A -> F,  B -> 8,
C -> 4,  D -> 7,  E -> 1,  F -> 2.

Почему именно он:
- Размер совпадает: у нас 4-битные нибблы, PRESENT тоже
  оперирует 4 битами.
- Готовый и проверенный: стандартный S-Box, прошедший
  многолетний криптоанализ.
- Хорошие криптографические свойства: нелинейность,
  отсутствие неподвижных точек, устойчивость к
  дифференциальному и линейному криптоанализу.
- Лёгкость: маленькая таблица, быстро работает.

Проверка корректности: все 16 выходных значений уникальны,
значит таблица — биекция, и обратная таблица строится
автоматически без коллизий.

----------------------------------------------------------------
2. РЕЖИМ ШИФРОВАНИЯ: PCBC (PROPAGATING CBC)
----------------------------------------------------------------
Проблема ECB: каждый блок шифруется отдельно, одинаковые
блоки дают одинаковый шифротекст. Это утечка структуры.

PCBC — режим с распространением ошибки по всей цепочке.

Формулы шифрования:
C[0] = E(P[0] XOR IV)
C[i] = E(P[i] XOR P[i-1] XOR C[i-1]),  i >= 1

Формулы расшифрования:
P[0] = D(C[0]) XOR IV
P[i] = D(C[i]) XOR P[i-1] XOR C[i-1],  i >= 1

Ключевая идея: на вход шифра подаётся XOR предыдущего
открытого текста и предыдущего шифротекста. Благодаря
этому ошибка в одном блоке портит все последующие.

Почему выбрали PCBC:
- Сильный лавинный эффект по всей цепочке.
- Нагляднее, чем CBC: цепочка идёт по двум каналам
  одновременно (и по P, и по C).
- Одинаковые сообщения при разном IV дают разный
  шифротекст.
- Не промышленный стандарт, но отличный учебный пример
  propagation-идеи.

----------------------------------------------------------------
3. ГЕНЕРАЦИЯ ПОДКЛЮЧЕЙ (KEY SCHEDULE)
----------------------------------------------------------------
Задача: из мастер-ключа длиной от 128 бит получить ровно
10 подключей по 64 бита — по одному на каждый раунд.

Алгоритм:
1. Берём первые 128 бит ключа, делим на L (64 бита) и
   R (64 бита).
2. Если ключ длиннее 128 бит — остаток разбиваем на
   64-битные куски и XOR-им по кругу в L и R. Так весь
   ключ влияет на подключи.
3. Для каждого раунда r = 1..10:
   L = L XOR ROTL(R, r)
   R = R XOR ROTL(L, r)
   подключ = L XOR R XOR r_64bit
   где ROTL — циклический сдвиг влево на r бит,
   r_64bit — номер раунда в 64-битном представлении.
4. Получаем 10 разных подключей.

Идея: циклический сдвиг на разное число бит в каждом
раунде + XOR со счётчиком раунда гарантируют, что все
10 подключей разные и зависят от всего ключа.

Важно: key schedule — детерминированная функция. Она НЕ
требует, чтобы ключ был кратен 64 битам. Если остаток
короче 64 бит, он дополняется нулями до 64 бит и
XOR-ится. Это часть key schedule, а не "паддинг ключа".

----------------------------------------------------------------
4. ПАДДИНГ ПО СТАНДАРТУ ISO 7816-4
----------------------------------------------------------------
Проблема: сообщение может быть не кратно 64 битам, а
блочный шифр работает только с целыми блоками. Простое
добавление нулей плохо — при расшифровании нельзя
отличить настоящие нули от добавленных.

Решение: паддинг ISO 7816-4 (OneAndZeroes).
- Добавляем один бит '1', затем столько '0', сколько
  нужно до кратности 64.
- Даже если длина уже кратна 64 — всё равно добавляем
  целый блок: '1' + 63 нуля. Это гарантирует, что
  разделитель всегда есть.
- При расшифровании ищем последний '1' справа и всё,
  что после него (включая сам '1'), отбрасываем.

Почему именно ISO 7816-4:
- Международный стандарт (умные карты, банковские
  системы).
- Однозначное восстановление границы: всегда есть
  маркер '1'.
- Простая реализация: rfind("1") — одна строка.
- Работает побитово, что удобно для нашего битового
  представления.

Примеры:
Было 300 бит -> стало 300 + 1 + 19 нулей = 320 бит (5 блоков)
Было 320 бит -> стало 320 + 1 + 63 нуля = 384 бита (6 блоков)

----------------------------------------------------------------
5. IV (INITIALIZATION VECTOR)
----------------------------------------------------------------
Что такое IV: случайное число размером с блок (у нас
64 бита), которое подмешивается в первый блок перед
шифрованием.

Зачем нужен:
- Без IV два одинаковых сообщения при одном ключе дают
  одинаковый шифротекст — утечка: злоумышленник видит,
  что сообщения повторяются.
- С IV первый блок шифруется как E(P[0] XOR IV).
  IV каждый раз разный -> шифротекст разный, даже если
  сообщение то же самое.

Свойства IV:
- Не секретный: передаётся открыто вместе с шифротекстом.
- Уникальный: генерируется заново при каждом шифровании.
- Размер = размер блока: 64 бита.
- Нужен при расшифровании: без него нельзя восстановить
  первый блок.

Аналогия: как соль для пароля. Не секретна, но делает
одинаковые пароли разными хешами.

В нашем коде: IV генерируется случайно, выводится в
BIN и HEX. Его нужно сохранить, чтобы потом расшифровать
сообщение тем же ключом.

----------------------------------------------------------------
6. ОБЩАЯ СХЕМА РАБОТЫ
----------------------------------------------------------------
Шифрование:
1. Ввод сообщения (BIN или HEX).
2. Паддинг ISO 7816-4 до кратности 64.
3. Разбиение на блоки по 64 бита.
4. Генерация 10 подключей из мастер-ключа.
5. Генерация случайного IV (64 бита).
6. Для каждого блока:
   - XOR с предыдущим P и C (или с IV для первого).
   - 10 раундов: XOR с подключом -> S-box -> сдвиг
     вправо на 3 (в последнем раунде S-box и сдвиг
     пропускаются).
7. Вывод шифротекста (BIN и HEX) и IV.

Расшифрование:
1. Ввод шифротекста, ключа, IV.
2. Разбиение на блоки по 64 бита.
3. Генерация тех же 10 подключей.
4. Для каждого блока:
   - 10 раундов в обратном порядке: XOR с подключом ->
     обратный сдвиг -> обратный S-box (в первом раунде
     обратные S-box и сдвиг пропускаются).
   - XOR с предыдущим P и C (или с IV).
5. Снятие паддинга: удаление последнего '1' и всех
   нулей после него.
6. Вывод исходного сообщения.
